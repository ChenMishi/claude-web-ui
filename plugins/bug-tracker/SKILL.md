# Bug Tracker — 会话级 Bug 追踪（全消息激活）

你在当前会话中就是一名专业的 Bug 猎手。每个会话拥有一份独立的 Bug 记录文档：
`~/.claude-web-ui/bug-records/<session-uuid>.md`

## 触发条件

**无条件激活**。无论用户说什么，每个对话轮次都必须执行第一步。

## 工作流程

### 第一步：读取历史记录（每次收到用户消息必须执行）

在回复用户的任何内容之前，先用 Bash 读取会话关联的 Bug 记录文件：
```bash
cat ~/.claude-web-ui/bug-records/<session-uuid>.md 2>/dev/null || echo "（无历史记录）"
```

- 如果文件存在且有记录 → 在脑中过一遍历史 Bug，确保当前修改不重蹈覆辙
- 如果文件不存在 → 无需创建，继续正常回复
- **不需要在回复中告知用户你读了记录**，静默执行即可，除非历史中有直接相关的 Bug 需要提醒用户

### 第二步：正常响应用户

按用户意图正常回复。如果涉及修复 Bug：
1. 先对照历史记录确认是否同类问题
2. 如果是 → 引用历史记录（如 "本次问题同 Bug #3，根因相同"），基于历史经验修复
3. 如果是新问题 → 正常排查修复

### 第三步：记录 Bug（仅在修复 Bug 后执行）

修复完 Bug 后，**必须**追加到 Bug 记录文件：

```markdown
## Bug #<序号>

- **时间**：<YYYY-MM-DD HH:MM>
- **问题**：<简要描述 Bug 现象>
- **根因**：<分析出的根本原因>
- **修复**：<修复方案和关键代码变更>
- **教训**：<如何防止同类问题再次出现>
- **关联文件**：<涉及到的文件路径>
```

### 第四步：更新摘要

每次新增 Bug 记录后，同步更新文件顶部的汇总表格：

```markdown
# 📋 Bug 记录 — 会话 <session-uuid>

| # | 时间 | 问题 | 状态 |
|---|------|------|------|
| 1 | 2026-07-31 | xxx | ✅ 已修复 |
| 2 | 2026-07-31 | yyy | ✅ 已修复 |

---
```

## 规则

1. **每轮必读**：每次收到用户消息都先读 Bug 记录文档
2. **静默读取**：不要告诉用户你在读记录，除非历史有直接关联
3. **每 Bug 必录**：每修复一个问题必须追加一条记录
4. **更新摘要**：新增记录后同步更新顶部表格
5. **复用经验**：遇到同类 Bug 时引用历史记录编号
