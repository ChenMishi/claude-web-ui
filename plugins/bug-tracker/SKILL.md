# Bug Tracker — 会话级 Bug 追踪

你在当前会话中就是一名专业的 Bug 猎手。每个会话拥有一份独立的 Bug 记录文档：
`~/.claude-web-ui/bug-records/<session-uuid>.md`

## 触发条件

当用户提到以下任一关键词时必须激活：
- "bug"、"Bug"、"BUG"、"bug"
- "修复"、"修一下"、"有问题"、"报错"、"不工作"、"没反应"
- "又出现了"、"反复"、"还是不行"

## 工作流程

### 第一步：读取历史记录（每次修复前必须执行）

用 Bash 读取会话关联的 Bug 记录文件：
```bash
cat ~/.claude-web-ui/bug-records/<session-uuid>.md 2>/dev/null || echo "（无历史记录）"
```

如果文件不存在，说明该会话尚未创建 Bug 记录，跳到第三步创建新文件。

如果文件存在，仔细阅读：
- 当前反馈的 Bug 是否与历史记录中的某个 Bug **相同或相似**？
- 如果是 → 先查看当时记录的**根因和修复方案**，**不要盲目重复修复**，基于历史经验提出更深层的方案
- 如果是新问题 → 继续排查

### 第二步：排查和修复

对每个 Bug：
1. 定位根因（root cause）
2. 设计修复方案
3. 实现修复
4. 验证修复有效

### 第三步：记录 Bug（每次修复后必须执行）

修复完成后，**必须**追加记录到 Bug 记录文件。使用 Edit 工具（追加模式）或 Write 工具写入以下格式：

```markdown
## Bug #<序号>

- **时间**：<YYYY-MM-DD HH:MM>
- **问题**：<简要描述 Bug 现象>
- **根因**：<分析出的根本原因>
- **修复**：<修复方案和关键代码变更>
- **教训**：<如何防止同类问题再次出现>
- **关联文件**：<涉及到的文件路径>
```

### 第四步：更新摘要

在文件顶部维护一个汇总表格：

```markdown
# 📋 Bug 记录 — 会话 <session-uuid>

| # | 时间 | 问题 | 状态 |
|---|------|------|------|
| 1 | 2026-07-31 | xxx | ✅ 已修复 |
| 2 | 2026-07-31 | yyy | ✅ 已修复 |

---
```

## 规则

1. **先查后修**：绝不跳过历史记录查询直接上手修 Bug
2. **每 Bug 必录**：每修复一个问题必须追加一条记录
3. **更新摘要**：新增记录后同步更新顶部表格
4. **复用经验**：遇到同类 Bug 时引用历史记录并说明关联（如 "本次问题同 Bug #3，根因相同，但表现在不同参数下触发"）
